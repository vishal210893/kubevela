# Addon CRD Manifest & Helm Wiring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile the `Addon` Go type into a CRD YAML with three printer columns and ship it in the vela-core Helm chart, verified by a live k3d smoke test.

**Architecture:** Add `+kubebuilder:printcolumn` markers to the existing `Addon` type, run KubeVela's marker-driven generation pipeline (controller-gen → `config/crd/base/` → `dispatch.go` → `charts/vela-core/crds/`), then verify structure, idempotency, and an install→apply→get→delete round-trip on a throwaway k3d cluster.

**Tech Stack:** Go, controller-gen (kubebuilder markers), KubeVela `hack/crd/dispatch`, Helm `crds/` convention, k3d, kubectl.

**Branch:** `feat/kep-2.13-addon-types` (stacks on stories 1.1 and 1.2). Do NOT create a new branch.

- [ ] **Step 2: Add the three printcolumn markers**

In `apis/core.oam.dev/v1beta1/addon_types.go`, locate the block (around line 93):

```go
// +kubebuilder:object:root=true
// +kubebuilder:resource:scope=Cluster,shortName=addon
// +kubebuilder:subresource:status
// +genclient
// +genclient:nonNamespaced
```

Insert the three marker lines immediately ABOVE `// +kubebuilder:object:root=true` so the block becomes:

```go
// +kubebuilder:printcolumn:name="PHASE",type=string,JSONPath=`.status.phase`
// +kubebuilder:printcolumn:name="VERSION",type=string,JSONPath=`.status.installedVersion`
// +kubebuilder:printcolumn:name="AGE",type=date,JSONPath=".metadata.creationTimestamp"
// +kubebuilder:object:root=true
// +kubebuilder:resource:scope=Cluster,shortName=addon
// +kubebuilder:subresource:status
// +genclient
// +genclient:nonNamespaced
```

Match the `Application` type's marker style exactly (`application_types.go:73-78`): backtick-quoted JSONPath for the two string columns, double-quoted for the date column.

## Task 4: Live k3d smoke test (AC4, AC5, AC6)

**Files:**
- Create: `$CLAUDE_JOB_DIR/tmp/example-addon.yaml` (throwaway)

- [ ] **Step 1: Create a throwaway k3d cluster**

Run: `k3d cluster create addon-smoke --wait --timeout 120s`
Then: `kubectl cluster-info`
Expected: control plane reachable. If creation fails on memory, retry once with `--servers 1 --agents 0`.

- [ ] **Step 2: AC4 — install the Addon CRD via the Helm path**

Run:
```bash
helm template vela-core charts/vela-core 2>/dev/null | kubectl apply --server-side -f - 2>&1 | grep -i addon || \
  kubectl apply --server-side -f charts/vela-core/crds/core.oam.dev_addons.yaml
kubectl get crd addons.core.oam.dev
```
Expected: `addons.core.oam.dev` CRD is Established. (If the full `helm template` apply is noisy or fails on unrelated templates, the targeted `kubectl apply` of just the CRD file satisfies AC4's intent — the CRD installs without conflict.)

- [ ] **Step 3: Write a minimal example Addon CR**

Create `$CLAUDE_JOB_DIR/tmp/example-addon.yaml`. Use only fields that exist in `AddonSpec` (verify required fields first with `grep -nE "json:\"" apis/core.oam.dev/v1beta1/addon_types.go` around the `AddonSpec` struct). Minimal example:

```yaml
apiVersion: core.oam.dev/v1beta1
kind: Addon
metadata:
  name: fluxcd
spec:
  version: "1.0.0"
```

If `kubectl apply` in Step 4 rejects it for a missing required field, add that field per the struct and retry — the goal is the minimum that the API server accepts.

- [ ] **Step 4: AC5 — apply the CR and confirm printer columns populate**

Run:
```bash
kubectl apply -f $CLAUDE_JOB_DIR/tmp/example-addon.yaml
kubectl get addons.core.oam.dev
kubectl get addons -o wide
```
Expected: the object lists with column headers `NAME PHASE VERSION AGE`. PHASE and VERSION may be empty (no controller writes status yet) — that is acceptable; AC5 checks the columns render and AGE populates. AGE shows a relative time like `5s`.

- [ ] **Step 5: AC6 — reverse smoke: delete CR and CRD cleanly**

Run:
```bash
kubectl delete -f $CLAUDE_JOB_DIR/tmp/example-addon.yaml
kubectl delete crd addons.core.oam.dev
kubectl get crd addons.core.oam.dev 2>&1 | grep -i "not found"
```
Expected: CR deletes immediately (no finalizer, no controller). CRD deletes cleanly and the final `get` reports `NotFound`. No hang.

- [ ] **Step 6: Tear down the cluster**

Run: `k3d cluster delete addon-smoke`
Expected: cluster removed.
